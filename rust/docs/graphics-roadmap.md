# 图形与动画升级路线（参考 Blender 的思路）

> 目标：把「TXT → 扁平 SVG 动画」升级为「TXT → 有体积感、有镜头语言的 3D 动画」，同时保持 wayhug.com 的既有边界（文稿驱动、四相世界观、无音乐、不涉宗教政治、MIT 免费授权至 2026-12-31）。
>
> 本文只讲**路线、工作量与验收**，不承诺具体日期；工作量按「一名熟悉 Rust/前端、有 AI 辅助的开发者」的有效工作日计。

---

## 1. 现状与差距

| 维度 | 现在（v1） | 目标（3D） |
|---|---|---|
| 场景表示 | `story.rs` 切句分幕 → `animate.rs` 生成 SVG 图形 + `@keyframes` | 同一分幕结果 → 3D 场景图（角色 / 道具 / 舞台 / 相机 / 灯光） |
| 视觉 | 扁平几何、纯色、无渐变、无位图 | 有体积、有光照、有材质、有景深与雾 |
| 镜头 | 每幕一个固定机位、4.2s 循环 | 分镜表驱动的推拉移摇、转场、节奏 |
| 性能 | 纯 DOM/SVG，几乎零成本 | 浏览器 WebGL/WebGPU，需要画质档位与降级 |
| 音乐 | 无音轨（保持） | 无音轨（保持） |

关键约束（来自服务器实测）：线上机器 **2 vCPU / 2GB RAM / 无独立 GPU**。
因此**渲染必须发生在访客浏览器**，服务端只负责产出「场景 JSON」，不能跑 Blender 出片。

---

## 2. 关于「参考 Blender 开源项目」的正确姿势

Blender 本体是 **GPL** 的桌面 DCC（建模/渲染/合成），不是网页渲染器：

- **不能**把 Blender 代码链接进本项目的 Rust 二进制，也不能把它的渲染器搬进网页——GPL 会传染，项目现在的交付口径是 MIT。
- **可以**把它当作**离线资产工坊**与**方法论来源**，这两件事都不带来许可证问题：

| 可参考的点 | 落地方式 |
|---|---|
| 场景集合 / 命名规范 | 资产与节点的命名约定（`char.fox`, `prop.letter`, `stage.dawn`） |
| 几何节点式程序化建模 | 用参数化图元 + 组合规则生成动物/道具，而不是手摆模型 |
| 着色器节点 → Toon/PBR | 把「基础色 / 粗糙度 / 自发光」映射成卡通材质参数 |
| 相机（焦距、景深、构图） | 分镜表里直接写 `lens / focus / height / angle` |
| F-Curve / NLA 分层 | 动画分层：`body` / `secondary` / `camera` / `fx` 四条轨道叠加 |
| 色彩管理（AgX/Filmic） | 调色参数化，四相各一套 LUT 风格，不引入位图 |

**资产出口统一用 glTF 2.0**（Khronos 开放标准）。Blender 只在你的电脑上用来建模与导出；网站只加载 `.glb`，从此与 GPL 无关。

## 3. 三条可选路线

| 路线 | 做法 | 优点 | 代价 | 结论 |
|---|---|---|---|---|
| **R0 现状** | 继续 SVG + CSS 关键帧 | 零依赖、极快、可被搜索引擎读到 | 观感天花板低 | 保留为**降级层** |
| **R1 浏览器 3D（推荐）** | three.js（MIT）或 Babylon.js（Apache-2.0）加载 glTF；Rust 只产场景 JSON | 许可证干净、生态成熟、移动端可跑 | 首屏体积与 GPU 兼容要治理 | **主线** |
| R2 服务端 Blender 渲染 | 服务器跑 `blender -b` 出帧再拼视频 | 观感最接近 Blender | 2 vCPU/2GB 无 GPU，一条 8 幕动画要跑十几分钟；GPL 分发与并发成本高 | 只做**线下出片工具**，不做线上 |
| R3 纯 Rust 3D（wgpu→WASM） | 自研渲染器 + 自研 glTF 管线 | 技术最"纯"、可深度定制 | 工期约为 R1 的 2–3 倍，浏览器兼容与包体风险高 | 观望，不上主线 |

推荐组合：**R1 主线 + R0 回退 + Blender 离线资产工坊**。

## 4. 分阶段计划与工作量

单位：有效工作日（不含等待反馈）。

| 阶段 | 内容 | 交付物 | 工作量 |
|---|---|---|---|
| **P0 选型与原型** | 用 three.js 跑通一个 glTF 动物 + 四相灯光；测桌面/移动帧率与首屏体积；确认许可证清单 | `proto/` 演示页、性能基线表、许可证说明 | **2–3 天** |
| **P1 场景编译器** | 新增 `stage.rs`：Story → 3D 场景（角色、道具、舞台、相机、灯光）；四相→光照/雾/色温，四属性→材质与粒子 | `/api/stage/{id}` 输出场景 JSON；单测覆盖四相映射 | **6–8 天** |
| **P2 时间轴与导演** | 新增 `anim3d.rs`：分镜表、镜头运动、缓动曲线、转场、确定性种子（= story fingerprint） | 同一 TXT 每次一致的镜头脚本；`?still=1` 定格 | **6–8 天** |
| **P3 Blender 资产工坊** | `.blend` 模板、命名规范、导出脚本（glTF）、10–20 个动物/道具资产；资产许可清单 | `assets3d/*.glb` + 制作手册 | **8–12 天**（美术占大头） |
| **P4 前端渲染器** | three.js 场景装配、按需加载、画质档位（低/中/高）、自动降级、深链、静态首帧 | `/watch/{id}/3d` 页面；SVG 回退开关 | **4–6 天** |
| **P5 治理与上线** | 性能预算、无障碍（`prefers-reduced-motion`）、SEO 静态预览、文档、灰度发布 | 上线检查表、README/文档更新 | **3–5 天** |

**合计**

- 可演示 MVP（1 个故事 + 1 套资产，桌面端可看）：**约 10–12 个工作日（2–2.5 周）**
- 可用 v2（多故事模板、移动端 30fps、SVG 回退、约 20 个资产）：**约 5–6 周**
- 接近 Blender 观感（材质/光照/景深/后期、50+ 资产、成体系的导演语法）：**约 10–14 周**，其中一半是美术与调色，不是写代码

按我这边常规推进节奏（每天 4–6 小时有效产出）：

- **第 2 周**：给你看第一版 3D 场景，同一篇 TXT 可在「扁平 SVG」与「3D」之间切换；
- **第 4 周**：v2 上线，默认仍是 SVG，3D 作为「精细呈现」入口，出问题随时切回；
- **第 8 周起**：根据你的审美反馈与资产积累，逐步把 3D 变成默认呈现。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 服务器无 GPU、内存小 | 渲染只在浏览器；服务端只出 JSON；构建仍用 `CARGO_BUILD_JOBS=1` |
| 移动端 GPU 差异大 | 画质档位 + 自动降级 + 首帧静态图；低端机直接走 SVG |
| 包体膨胀 | three.js 按需引入、glTF Draco 压缩、非首屏懒加载；预算：首屏增量 ≤ 300KB |
| GPL 传染 | Blender 仅离线使用；产物 glTF；二进制不链接 GPL |
| 观感依赖美术 | P3 单独排期；先做 3–5 个"招牌动物"，其余用参数化生成 |
| 失去确定性 | 所有随机取 `story.fingerprint` 作种子；同一 TXT 输出一致 |
| 内容边界 | 继续走 `guard.rs`；3D 资产命名与文案同样过滤 |

## 6. 验收标准（可测）

1. 同一 TXT 两次生成，镜头与动作完全一致（种子=指纹）。
2. 桌面 1080p 中档画质 ≥ 50fps；移动中档 ≥ 30fps；低端自动降级。
3. 首屏 JS 增量 ≤ 300KB；3D 资源懒加载，不拖慢首页。
4. 无 `<audio>`、无自动播放（保持现状）。
5. 无 WebGL 时自动回退 SVG，`?still=1&scene=N` 仍可定格。
6. 开启 `prefers-reduced-motion` 时输出静态关键帧。
7. 证书、许可、写作口令、领证链路不受影响（回归测试通过）。

## 7. 需要你拍板的三件事

1. **观感优先级**：要「动画电影的镜头感」，还是「插画绘本的静态美 + 轻微动效」？（前者走 R1 全套，后者工期可省 30–40%）
2. **资产边界**：先只做 3–5 个招牌动物（狐/兔/鸮/熊…），其余参数化生成，是否可接受？
3. **默认呈现**：3D 做「精细呈现」入口（默认 SVG），还是一开始就替换默认首页动画？

确认这三点后，P0 我可以直接开工，两天内给出一版能在浏览器里转起来的 3D 原型。
